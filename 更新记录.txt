【主要做了什么】
把本地已经跑通的整套选股系统第一次推到 GitHub，作为项目的起点。

1. stock_agent/ —— FastAPI 后端服务（26 个文件）
   · app.py / service.py / cache.py / config.py：服务骨架
   · providers/：行情数据源（东方财富为主，新浪 / 腾讯备用）
   · screener/：选股引擎
       - store.py       本地 SQLite 日线缓存
       - context.py     单只股票的指标预计算
       - patterns.py    二次涨停（美人肩）形态判定 + 打分模型
       - lowpos.py      低位均线粘合形态
       - strategies.py / trend.py   其他形态策略
       - scanner.py     候选池 → 并发取数 → 判定 → 排序
       - cli.py         命令行入口

2. web/ —— 前端页面
   · index.html    实时行情工作台（分时 / K线 / 盘口 / 自选 / 排行）
   · mrj.html      美人肩选股看板（K线 + MACD + 作战手册）
   · backtest_classic.html / backtest_broad.html   自包含回测报告
   · style.css / mrj.css / app.js / mrj.js / vendor/echarts.min.js

3. .pi/skills/ —— 4 个选股技能文档
   lowpos-scan（低位票）、meirenjian-classic（经典美人肩）、
   meirenjian-broad（广义美人肩）、steady-climb-scan（趋势票）

4. research/ —— 研究脚本（42 个）与回测产物
5. tools/ —— 每日扫描、Windows 计划任务注册等辅助脚本
6. 根目录 —— run.py 启动入口、start.bat / start.sh、requirements.txt、
   README.md、.gitignore、低位票 30 万回测报告（2 个 HTML + 2 个 CSV）

【当时遗留的问题】
· 网页必须靠后端服务提供，直接双击 web/mrj.html 打开会没样式、也扫不出结果
· 每次启动都要手动敲 python run.py，再手输网址
· 选股看板只有一套「涨停后横盘」宽口径（横盘 3~15 天、收盘 ±7%），
  无法区分经典美人肩 / 广义美人肩 / 低位票
· start.bat 是 LF 换行，cmd 解析多行 if 块可能出错

第 2 次更新 · 选股看板支持三模式 + 一键启动
======================================================================

时间：2026-10-19 22:56
提交：f5584b8（报告归位）、7be1222（三模式）
分支：feature/three-modes   → 待合并进 main
规模：+1124 / −230 行，改动 9 个文件（另有 4 个回测报告改名归位）

【主要做了什么】

一、选股看板区分三种模式（核心改动）
    以前只有一套宽口径，现在拆成三条独立口径，各自独立扫描：

    1) 经典美人肩   锚点涨停/准涨停 9.4%~10.5%，横盘 4~8 天，
                    收盘震幅 ±3.5%，日均振幅 ≤4%，量能趋势 ≥0.9
    2) 广义美人肩   锚点大涨未封板 4%~9.4%，横盘 3~8 天，
                    收盘震幅 ±4%，其余条件同上
    3) 低位票       250 日回撤 ≥30% + 低位均线粘合（离散度 ≤2.5%）
                    + 拐头（5 日内 MA5 上穿 MA10）或放量突破（涨幅 ≥4%）

    顶部加了三张模式卡，点一下即切换；过滤器、卡片指标、详情体检项
    都跟着模式变化；网址支持 ?mode=classic / broad / lowpos 直接跳转。

二、后端
    · api/mrj.py 重写：/stats、/scan、/detail 三个接口都增加 mode 参数，
      三种口径与回测数字统一到 MODES 常量里维护
    · 扫描结果与详情统一成一套数据结构（卡片指标、体检清单、作战手册），
      前端不再写死某一种形态的字段
    · screener/lowpos.py 新增 lowpos_checklist()，把低位票硬条件
      拆成可展示的勾选清单（不改动原判定逻辑）

三、修复 Bug
    · screener/scanner.py：SQL 预筛阈值原来写死 9.5%，导致「广义美人肩」
      （锚点 4%~9.4%）在预筛阶段就被全部丢掉，永远扫不出票。
      改为跟随 cfg.anchor_min_gain 动态取值

四、一键启动
    · run.py：新增 --page（启动后打开哪个页面，默认 /mrj）与 --no-open；
      增加「等端口就绪再开浏览器」的后台线程，避免抢跑报错
    · start.bat：双击后弹菜单选模式（1 经典 / 2 广义 / 3 低位 / 4 行情台 /
      0 不开浏览器），选完自动打开对应页面；检测到 8000 端口已有服务时
      直接打开页面而不是报错退出

五、工程
    · 新增 .gitattributes，锁定 *.bat / *.cmd / *.ps1 为 CRLF，
      避免 cmd 解析 if / goto 多行块失败
    · 4 个低位票回测报告（HTML + CSV）从仓库根目录归位到 web/ 目录

【实测结果（数据日 2026-10-16 收盘）】
    经典美人肩    0 只   （口径极严，五年年均约 30 次机会，空结果是正常的）
    广义美人肩   16 只
    低位票       52 只

    五年 30 万组合回测：
      经典 +61.3%（最大回撤 12.6%，PF 1.46）
      广义 +122.0%（最大回撤 28.0%，PF 1.16）
      低位 +384.9%（年化 31.4%，最大回撤 19.2%）

【使用方式】
    双击 start.bat → 选序号 → 浏览器自动打开
    或命令行：
      python run.py                            默认打开 http://127.0.0.1:8000/mrj
      python run.py --page /mrj?mode=lowpos    直接打开低位票页
      python run.py --no-open                  只起服务，不开浏览器
      start.bat broad                          一步直达广义美人肩
